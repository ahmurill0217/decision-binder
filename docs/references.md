# Reference inspection before implementation

Inspected on 2026-10-27 (America/Los_Angeles).

- [Ford article](https://medium.com/@colbyford/zero-shot-classification-of-protein-binders-with-jev-634b0300e58d): motivation and zero-shot comparison. Its full-cohort notebook is the implementation reference, not the balanced demonstration sample.
- [Adaptyv preprocessing notebook](https://github.com/colbyford/jev-binder-classification/blob/main/classify_binders_adaptyv.ipynb): 16 metrics × 5 summaries, five metadata fields, resolved labels only, complete-case filtering. No stoichiometry or target-form filter is present. Its printed cohort is 1,082 with 294 binders, reproduced by our pooled comparator.
- [Dataset](https://huggingface.co/datasets/Anthropic/claude-protein-binder-design): inspected card, rendered column dictionary, DATA_NOTES, INSILICO, and lookup tables. Dataset revision is pinned in config. Only tabular sources are downloaded by the pipeline.
- [Liquid SFT notebook](https://github.com/Liquid4All/cookbook/blob/main/finetuning/notebooks/sft_for_decision_models_with_trl.ipynb): BANKING77 examples become prompt/completion pairs with seeded, shuffled option subsets. Model-native rendering and tokenizer aliases map the answer to a code plus EOS. Completion-only loss is used. LoRA rank 16, alpha 32, dropout .05 targets language attention/convolution/MLP projections and excludes the vision tower. `SFTTrainer` receives the wrapped model, `SFTConfig`, train/eval datasets, and tokenizer via `processing_class`; one epoch, batch 4, accumulation 4, learning rate 2e-4. Evaluation calls `system_one_batch` and compares predicted intent to the label.
- [d1-3B model card](https://huggingface.co/LiquidAI/d1-3B) and [prompt.py](https://huggingface.co/LiquidAI/d1-3B/blob/main/prompt.py): decision inputs require model-specific serialization and single-token answer aliases, not an assumed generic chat template. Remote code and model license require review before a later model run.

The inspected Liquid notebook pins Transformers 5.19.0, TRL 1.15.0, and PEFT 0.21.2. These versions were used for CPU preflight, the completed Colab T4 training run, and adapter evaluation. Section 5 used the pinned native System One API for the original model; Section 7 used the same API with the adapter active. The source article/notebook informs preprocessing, but its reported model scores are not reproduced here and its evaluation cohort is not our 161-example test split. See [licensing](licensing.md) and [reproducibility](reproducibility.md).
